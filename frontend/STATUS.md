## Исправления по FRONTEND_REVIEW (ревизия 55686dd)

Все четыре группы замечаний подтвердились на коде и исправлены. Каждое покрыто тестом, который проверяет **правильное** поведение (`src/test/review.test.tsx`). Тесты воспроизведения из `review.audit.test.tsx` в эту ветку не переносились: они подтверждают ошибку, а не исправление. Их сценарии переписаны с правильными ожиданиями.

1. **Отчёт проверок больше 200 строк.** Отчёт загружается целиком (`lib/pages.ts: fetchAllPages`, страницы по 200; при смене `reportRevision` загрузка начинается заново). FAIL/PASS считаются только по полному набору. Таблица разбита на страницы по 50, а `?rowId=` открывает нужную страницу и выделяет строку; если строки нет, выводится предупреждение. Сводка и список заявок из проверки используют ту же полную загрузку. Каталоги скриптов, датасетов, прогонов и конфигураций тоже грузятся всеми страницами, а не первой.
2. **Состояние ошибки JSON.** `JsonParams` сообщает о валидности при внешней смене параметров, сбрасывается по `resetKey` (выбор другого скрипта с такими же параметрами) и при удалении редактора. Отключение проверки в конфигурации снимает её ошибку. `WorkspacePage` передаёт `paramsValid` в `WorkspaceRun`: при невалидном JSON запуск заблокирован, рядом показана причина.
3. **Старые ячейки сводной.** Ответ pivot хранится вместе со снимком своего запроса: подписи фильтров, token и ссылка «назад» берутся из одного ответа. На время пересчёта ячейки отключены, показывается полоса «Пересчитываем…». `Async` во время любого обновления затемняет прежние данные и блокирует действия с ними, не пересоздавая дерево.
4. **Смена прогона во время проверки.** Задача включения хранит пару `{runId, executionId}`. Опрос и ссылка на отчёт идут по этому прогону, а выбор прогона и датасета заблокирован, пока задача выполняется.

Дополнительно:
- **Нестабильный тест ошибки Python** теперь ждёт доступности кнопки; 5 изолированных запусков подряд — зелёные.
- **Демо на Windows:** `npm run dev:mock` = `vite --mode demo` с `.env.demo`, без синтаксиса оболочки. В README добавлены варианты для PowerShell и cmd. Флаг `VITE_USE_MOCK_API` сравнивается без учёта пробелов и регистра (cmd-вариант `set X=true && …` добавлял пробел к значению).
- **Защита от отсутствующего `scrollIntoView`** в jsdom: из-за него падала отрисовка в тесте.

## Готово

- Каркас React + TS + Vite, маршруты, светлая и тёмная темы, адаптивная вёрстка.
- Единый `ApiClient`: `HttpApiClient` (реальный API — по умолчанию) и `MockApiClient` (только при `VITE_USE_MOCK_API=true`, с баннером).
- Вход и выход, текущий пользователь, истёкшая сессия (401 → вход на том же URL), cookie-сессия и CSRF.
- Конфигурации: список, создание и редактирование, выбор датасета, процедур (FILE / рабочая область), проверок, JSON-параметров, ИИ; «Сохранить и запустить», повторный запуск.
- Запуск: этапы, `processed/total`, если сервер их знает (процент не выдумывается), журнал по курсору, переход к коду этапа, опрос раз в секунду только пока запуск активен, восстановление после перезагрузки.
- Отчёт открывается только при `reportReady`; при FAILED — ошибка этапа и ссылка на код.
- Сводка: KPI из API («нет данных» ≠ 0), матрица переходов решений, частые изменения с переходом в сводную, сводка проверок, время этапов, источник и время вычисления.
- Сводная: строки, колонки и фильтры с перестановкой и переносом полей, быстрые фильтры (только отличия, смена решения, продукт, партнёр), многоуровневые заголовки, тепловая подсветка, пагинация групп, PIVOT_TOO_WIDE, раскладка в URL.
- Переход: клик по ячейке → список уникальных заявок по `drilldownToken` с подписями контекста → карточка заявки (решения, разрезы, наблюдаемые изменения, атрибуты группы или все, фильтр отличий) → выделенный атрибут по PATH + ARRAY_KEY → исходные JSON BEFORE и AFTER по запросу. DRILLDOWN_EXPIRED обрабатывается.
- Отчёт проверок: единая таблица, LOW бледно, METRIC как есть, «показано N из CNT», переход к APP_IDS (CHECK_SAMPLE), фильтры FAIL и LOW, подсветка `?rowId=` из HTML.
- Новая проверка: из отчёта или рабочей области → `check-executions` → пересборка отчёта. Ошибка исполнения показывается как ошибка, не как PASS.
- Рабочая область Python: CodeMirror, тип, параметры, шаблон и контракт с сервера, сохранение, предпросмотр на датасете или прогоне, stdout/stderr/диагностика/строки, копирование FILE в рабочую область.
- ИИ-блок (все статусы, STALE с оговоркой) и HTML: открыть по ссылке, скачать с проверкой HTTP-статуса.
- ErrorBoundary; временные ошибки опроса не обрывают отслеживание задач.
