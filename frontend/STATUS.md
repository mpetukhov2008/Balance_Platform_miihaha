# Статус frontend (Claude)

Обновлено: 07.11.2026. Ветка `claude/frontend` от `origin/codex/backend@c26770c`. В `main` не сливается.

## Готово

- Каркас React + TS + Vite, маршруты, светлая и тёмная темы, адаптивная вёрстка.
- Единый `ApiClient`: `HttpApiClient` (реальный API — по умолчанию) и `MockApiClient` (только при `VITE_USE_MOCK_API=true`, с баннером).
- Вход и выход, текущий пользователь, истёкшая сессия (401 → вход на том же URL), cookie-сессия и CSRF.
- Конфигурации: список, создание и редактирование, выбор датасета, процедур (FILE / рабочая область), проверок, JSON-параметров, ИИ; «Сохранить и запустить», повторный запуск.
- Запуск: этапы, `processed/total`, если сервер их знает (процент не выдумывается), журнал по курсору, переход к коду этапа, опрос раз в секунду только пока запуск активен, восстановление после перезагрузки.
- Отчёт открывается только при `reportReady`; при FAILED — ошибка этапа и ссылка на код.
- Сводка: KPI из API («нет данных» ≠ 0), матрица переходов решений, частые изменения с переходом в сводную, сводка проверок, время этапов, источник и время вычисления.
- Сводная: строки, колонки и фильтры с перестановкой и переносом полей, быстрые фильтры (только отличия, смена решения, продукт, партнёр), многоуровневые заголовки, тепловая подсветка, пагинация групп, PIVOT_TOO_WIDE, раскладка в URL.
- Переход: клик по ячейке → список уникальных заявок по `drilldownToken` с подписями контекста → карточка заявки (решения, разрезы, наблюдаемые изменения, атрибуты группы или все, фильтр отличий) → выделенный атрибут по PATH + ARRAY_KEY → исходные JSON BEFORE и AFTER по запросу. DRILLDOWN_EXPIRED обрабатывается.
- Отчёт проверок: единая таблица, LOW бледно, METRIC как есть, «показано N из CNT», переход к APP_IDS (CHECK_SAMPLE), фильтры FAIL и LOW, подсветка `?rowId=` из HTML.
- Новая проверка: из отчёта или рабочей области → `check-executions` → пересборка отчёта. Ошибка исполнения показывается как ошибка, не как PASS.
- Рабочая область Python: CodeMirror, тип, параметры, шаблон и контракт с сервера, сохранение, предпросмотр на датасете или прогоне, stdout/stderr/диагностика/строки, копирование FILE в рабочую область.
- ИИ-блок (все статусы, STALE с оговоркой) и HTML: открыть по ссылке, скачать с проверкой HTTP-статуса.
- ErrorBoundary; временные ошибки опроса не обрывают отслеживание задач.

## Проверено с реальным backend

Локально: `codex/backend@c26770c`, SQLite, `EXECUTION_MODE=trusted-local` (Docker на машине нет), `FULL_DATA_ROOT` → data из `main` (2002 пары). Браузер — встроенный в Claude Desktop, через Vite proxy.

- Вход и выход двух пользователей (`analyst`, `analyst2`): у второго пустой список запусков и 404 на чужой запуск.
- Конфигурация через UI на полном датасете → запуск → живой прогресс (NORMALIZE 4004/4004) → перезагрузка восстанавливает состояние → SUCCEEDED за 42 с.
- Сводка: 2002 заявки, 502 с различиями, 385 со сменой решения, переходы 273 + 112 = 385, 167 при смене внешних данных.
- Сводная 53 группы → «Только отличия» → ячейка `characteristics.score_okb`, AFTER → 167 заявок, контекст сохранён → заявка I32554362 → атрибут выделен автоматически (760 → 620).
- Отчёт проверок: 32 строки → новая проверка из рабочей области (CNT 385 / TOTAL 2002, APP_IDS 20) → ревизия 2, 33 строки; «показано 20 из 130» → список CHECK_SAMPLE.
- HTML: `report.html` 200 с `attachment`, ссылки ведут в `/runs/:id` и `/checks?rowId=`; ссылка открывает и выделяет строку, без сессии — вход и возврат на неё. Неверный id → 404, файл не сохраняется.
- ИИ: UNAVAILABLE «Провайдер ИИ не настроен» показан честно.
- Ошибки: запуск с ломающимся COMPARE → FAILED, этап и KeyError, отчёт закрыт, переход к коду этапа; предпросмотр того же скрипта → «Ошибка выполнения».
- Найдено и исправлено при интеграции: падение при выходе (новый Chrome возвращает Promise из `scrollIntoView`) и обрыв отслеживания проверки на временной ошибке 500.

## Не проверено

- Docker-исполнитель и PostgreSQL (на машине нет Docker); скорость pivot на PostgreSQL.
- Реальный ИИ-провайдер (READY/STALE с текстом — только в тестах на демо-данных).
- Скачивание файла кнопкой в браузере (проверен fetch того же endpoint и обработка ошибок).
- PIVOT_TOO_WIDE от реального сервера (на этих данных он не возникал; ветка проверена в демо).
- Мобильная вёрстка — только базовая адаптация.
