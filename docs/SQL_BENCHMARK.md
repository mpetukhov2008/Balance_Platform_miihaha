# Замер запросов отчёта

06.11.2026. Локальная Windows-среда, Python 3.12, SQLite. Искусственный набор: повторение четырёх samples с новыми APP_ID, всего 2002 заявки. В SQL записано 297770 строк сравнения, 1148 агрегированных facts и 574522 связей facts → заявки. Это не полный выданный data и не его эталон.

После переноса агрегации в SQL и добавления покрывающих индексов, пять последовательных измерений:

| Запрос | Медиана, мс | Максимум, мс |
|---|---:|---:|
| Pivot: PATH × SOURCE/DIFF_FLAG, первые 50 групп | 317.24 | 357.56 |
| Список изменившихся заявок, первые 50 | 132.31 | 149.06 |

Измерены только SQL-запросы и формирование их результата в Python. Не входят HTTP, запись drilldown tokens, браузер, нормализация, Python executor и публикация запуска. При повторении samples число уникальных facts остаётся небольшим: набор с почти уникальными значениями может вести себя иначе.

Обнаруженное узкое место: JOIN фактов с каждой связью заставлял SQLite многократно читать большие JSON payload. Отбор fact ordinal отдельным подзапросом и покрывающие индексы избавили запрос от этих чтений. До покрывающих индексов pivot занимал около 3.6–4.5 с, список заявок — 3.0–4.5 с в этой же среде.

Воспроизведение: `python -m backend.benchmark --apps 2002 --repeats 5`. Результат сохраняется в runtime/benchmark.json. Нужны samples. Для реальной приёмки повторить на полном data, в PostgreSQL и через HTTP вместе с frontend. Скорость на 20000 заявках пока не подтверждена.
