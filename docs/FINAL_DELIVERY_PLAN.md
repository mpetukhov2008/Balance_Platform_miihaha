## 2. Подключить и продемонстрировать ИИ

Место ИИ в процессе: нормализация → сравнение → агрегаты → Python-проверки → независимое мнение языковой модели → публикация единого отчёта.

- Первый кандидат — YandexGPT Pro 5.1 через Yandex AI Studio. Выбор и передачу данных согласовать с командой/заказчиком; доступ и API-ключ пока являются зависимостью. Ключ хранить только на сервере, в чат и репозиторий не помещать.
- Подготовить вход: общие показатели, переходы решений, частые изменения, результаты проверок и краткий предметный словарь. Не отправлять всю витрину, исходные JSON и APP_IDS. Ограничивать объём структурированно, не обрезанием строки JSON.
- Адаптировать авторизацию и настройки API выбранного провайдера, получить настоящее заключение на полном прогоне.
- Формат заключения: существенные изменения, подозрительные сочетания, гипотезы с опорой на факты, что аналитику проверить дальше. Числа и PASS/FAIL рассчитываются кодом; ИИ даёт второе мнение.
- Добавить повторную генерацию по готовому отчёту: текущая кнопка «Обновить» лишь перечитывает сохранённый ответ. Фоновая задача, доступный статус, ошибки и привязка к ревизии отчёта.
- После новой проверки показывать старое мнение как STALE; не выдавать его за анализ новой ревизии.
- Проверить ответ, тайм-аут, недоступность провайдера и устаревание. Ошибка ИИ не должна закрывать вычисленный отчёт.
- Готово, когда реальное мнение отображается в UI и HTML и не искажает проверенные числа. При отсутствии доступа честно обозначить незавершённость; статический текст не заменяет интеграцию.
- Обучение собственной модели в план не входит: исходное задание требует обращения к языковой модели.
