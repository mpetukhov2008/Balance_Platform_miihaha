# Проверка безопасности 8 ноября 2026 года

Область проверки: код API и worker, аутентификация и владение объектами, CSRF, обработка ZIP и ограничение ресурсов, исполнение Python, HTML и браузерный клиент, контейнеры, зависимости, workflow и текущие файлы репозитория. Основа — категории OWASP Top 10 и воспроизводимые негативные тесты. Это проверка исходников и тестовой установки, а не независимый аудит внешнего сервера, TLS и инфраструктуры.

## Исправленные проблемы

| Проблема | Риск | Изменение и подтверждение |
|---|---|---|
| ZIP буферизовался до проверки сессии | Посторонний клиент мог расходовать память загрузкой большого тела | Сессия, срок, CSRF и Origin проверяются до чтения тела; не более двух принятых загрузок одновременно; ASGI-тест запрещает даже вызов receive для отклонённого запроса |
| compare_digest со строкой вне ASCII | Некорректный CSRF мог вызвать 500 вместо отказа | Сравниваются UTF-8 bytes; регрессионный тест |
| API-контейнер работал от root | Избыточные права при компрометации процесса | UID 65534, read-only root, tmpfs для временных данных, cap_drop ALL, no-new-privileges, ограничения PID/памяти; API-образ не содержит Docker CLI и не получает socket |
| Ключ ИИ передавался API без необходимости | Увеличение числа процессов с секретом | Настройки ИИ получает только worker; API ставит задания в очередь |
| trusted-local наследовал серверные секреты | Доверенная процедура могла случайно вывести секреты окружения | Минимальное окружение дочернего Python; тест с AI_API_KEY и DATABASE_URL. Режим всё ещё не является песочницей и имеет доступ к файлам пользователя |
| pytest 9.0.2 | Аудитор сообщил PYSEC-2026-1845 / CVE-2025-71176, локальная проблема временных каталогов на UNIX | Версия обновлена до 9.0.3. Это зависимость тестирования, а не установленный факт удалённого взлома приложения |
| Избыточные возможности workflow | Лишний доступ токена и сохранённые git credentials | permissions contents:read, checkout persist-credentials:false; добавлен аудит зависимостей в CI |

## Что уже защищено и перепроверяется

- Серверная проверка владельца конфигураций, скриптов, запусков, сырых данных, HTML и токенов детализации; чужой объект возвращает 404.
- HttpOnly/SameSite cookie, сроки сессий, scrypt, ограничение параллельных хеширований, CSRF и Origin для изменений. Публичный режим требует PostgreSQL, Docker, HTTPS и secure cookie.
- Сохраняемые атомарные лимиты входа, регистрации, API, очереди, запусков, загрузок и запросов/токенов ИИ.
- SQLAlchemy с параметризованными запросами; серверная проверка имён измерений и ограничение ширины/страниц сводной.
- ZIP не извлекается в файловую систему. Проверяются размеры, пары, JSON, UTF-8, идентификаторы, дубли, опасные пути и символьные ссылки.
- HTML экранирует данные; браузер не вставляет произвольный HTML. Настроены CSP, nosniff, запрет встраивания и no-store для ответов с данными.
- Docker-runner без сети, host mounts, socket, root и секретов; ограничения времени, памяти, CPU, PID, вывода и временного каталога проверяются в настоящем Docker CI.
- Backup проверяется контрольной суммой и восстановлением в отдельную БД. Дампы и `.env` не должны попадать в Git.

## Зависимости и секреты

`npm audit --json` на момент проверки сообщил **0 известных уязвимостей**. Python lock проверен pip-audit; найденная уязвимость pytest устранена обновлением. Результат аудита зависит от базы известных уязвимостей на момент запуска и не доказывает отсутствие неизвестных проблем. Команды повторения находятся в workflow Security.

Текущий репозиторий приватный. Релиз с командным `team-local.env` существует и доступен участникам с правами на репозиторий; содержимое ключа не выводилось в отчёт. Такой релиз нельзя оставлять при переводе репозитория в публичный доступ. После завершения мероприятия владельцу следует отозвать/заменить командный ключ и выдать отдельные доступы по необходимости. Перевод приватности и ротация ключа этим изменением автоматически не выполняются.

## Границы защиты

Один worker остаётся привилегированной инфраструктурной частью с Docker daemon. Для исполнения враждебного кода в публичном сервисе нужен выделенный worker-хост и дополнительная изоляция; контейнер использует общее ядро ОС. trusted-local допустим только для проверенного кода локальной демонстрации. Внешние HTTPS proxy, доверенные forwarded IP, обновления ОС/образов, мониторинг, свободный диск и отдельное защищённое хранилище backup остаются обязанностью эксплуатации.

Проверка не включает нагрузочный DDoS на внешний сайт, сканирование неизвестного хостинга, независимое доказательство отсутствия уязвимостей или переписывание истории Git. В текущем дереве убраны материалы передачи работ, устаревшие статусы и имена инструментов; исходные материалы организаторов и данные сохранены.

Источники методики: [OWASP Top 10](https://owasp.org/projects/top-ten), [база Python advisory](https://github.com/pypa/advisory-database), [pip-audit](https://github.com/pypa/pip-audit). Сообщения об уязвимостях направляйте команде приватно, без публикации секретов.
