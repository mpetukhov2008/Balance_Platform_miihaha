# Статус серверной части

## Реализовано

- API v0.1: сессии, CSRF, каталоги, конфигурации, пользовательские скрипты, очередь запусков, журнал, прогресс по этапам, сводка, pivot, drill-down, атрибуты/raw, проверки, HTML, статус ИИ.
- Отдельный worker и executor. Docker runner по умолчанию; trusted-local только явно для разработки и тестов.
- Настраиваемые исключения, ключи массивов, векторы по индексу, составные ключи, бакеты, сравнение исходных значений и четырёх типов изменений.
- Все пять checks исполняются без изменения их исходников через индексированный MartAPI.
- SQL-хранение с индексами заявок/путей/различий. PostgreSQL в Compose, SQLite для локальной проверки. Один worker.
- Снимок Python-кода при постановке задания, снимок raw-ответов при прогоне; журнал ведёт к текущему коду.
- Новая проверка пересобирает отчёт; одинаковый CHECK.id заменяет предыдущие строки. HTML экранируется.
- Для четырёх реальных samples вычислено: 1148 нормализованных строк обоих срезов, 595 строк сравнения, 3 заявки с различиями, 2 со сменой решения.

## Проверено

`python -m pytest -q`: 14 passed. Использованы отдельные SQLite-базы, реальные samples, trusted-local executor. Проверены ключи массивов/вектора, типы и бакеты, сквозной API, пять проверок, разделение пользователей, CSRF, повторный CHECK, HTML escaping, точный контекст pivot на смешанных атрибутах, timeout и лимит вывода.

Есть предупреждение Starlette о будущей замене TestClient/httpx; тесты проходят. OpenAPI экспортирован в contracts/openapi.json. Это не проверка frontend, PostgreSQL, Docker-изоляции или полного data.

## Блокировки и оставшиеся проверки

- Полный data/ не предоставлен: эталон полного прогона, скрытые данные и производительность 2002/20000 заявок не подтверждены.
- Docker daemon на момент проверки не работал. Контейнеры и PostgreSQL не запускались.
- Не предоставлены настройки реального провайдера ИИ. Без них возвращается UNAVAILABLE.
- Frontend ещё не получен от Claude. Реальная интеграция UI не подтверждена.
- Автоматическая проверка повторно отклонила публикацию исходных материалов, включая технические docs/checks, несмотря на общее разрешение владельца. В ветке только созданный код; исходники остаются локальными. Реальные sample-тесты в CI явно пропускаются; независимый synthetic API-тест выполняется.
- Pivot, фильтры и пагинация списка заявок перенесены в SQL. Добавлена индексированная таблица связей. На искусственном replay 2002 samples (297770 строк сравнения) медиана SQL pivot — 317 мс, списка заявок — 132 мс; это не замер полного data или HTTP. См. docs/SQL_BENCHMARK.md.

## Claude: что можно подключать сейчас

Использовать HTTP-клиент по API_CONTRACT.md, Vite proxy `/api`, cookie с credentials и CSRF token из login. Начать с datasets → scripts → configurations → runs. До запуска worker очередь останется QUEUED. Полный датасет каталога UNAVAILABLE до его подключения. Новая проверка в редакторе создаётся как WORKSPACE Script и запускается через check-executions.

Для отдельной рабочей копии взять ветку codex/backend; изменения frontend вести в claude/frontend. Файлы backend/, infra/, contracts/ не менять параллельно без записи запроса в frontend/CONTRACT_REQUESTS.md.

Добавлены CI-задача PostgreSQL и независимый synthetic API-тест. Их результаты на новой ревизии нужно проверить отдельно. Старые успешные CI-прогоны относились к прежней ревизии без исходных samples.
